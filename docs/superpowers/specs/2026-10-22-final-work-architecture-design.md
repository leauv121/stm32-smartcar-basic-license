# 自动驾驶小车最终工程架构设计

## 1 目标

在现有 STM32F103 智能小车工程基础上建立可持续扩展的最终大作业工程。保留已经完成的电机、循迹、MPU6050、OLED、按键和串口能力，把现有但未启用的轮速、颜色、超声波、灯光和电池采样重新接入统一的非阻塞框架，并为普通驾照和高级驾照任务提供独立状态机。

工程必须具备集中检错机制。任一模块出现可检测故障时，系统应记录模块、故障码、严重程度和时间；OLED 优先显示当前最高优先级故障，严重故障触发安全停车。OLED 自身不可用时，串口与核心板 LED 作为后备诊断通道。

## 2 范围

本阶段实现以下内容：

- 克隆并保留原工程的 CubeMX、HAL、Keil 和 IAR 配置。
- 建立配置层、驱动层、控制层、服务层和应用层的文件边界。
- 接入当前已启用的混合循迹、MPU6050 DMP、Yaw 计圈、电机、OLED、按键和串口代码。
- 接入已有的轮速、TCS34725、HC-SR04、左右灯和电池采样代码，但通过功能开关和自检结果控制启用状态。
- 建立普通驾照和高级驾照状态机接口、安全等待状态和紧急停车入口。
- 建立集中故障管理、上电自检、运行时监测、OLED 故障页、串口诊断和 LED 后备报码。
- 为不依赖硬件寄存器的状态机和故障管理逻辑建立主机侧测试。
- 执行 Keil Rebuild，确认目标工程可以生成 HEX。

本阶段不宣称完成以下内容：

- 普通驾照全赛道实车验收。
- 高级圆圈、八字和挑战路线实车验收。
- 未经实测的 PID、颜色、超声波、轮速和电池参数标定。
- 烧录、传感器接线和机械结构的物理验证。

## 3 设计原则

### 3.1 保留自动生成代码边界

CubeMX 生成的 `main.c`、`gpio.c`、`adc.c`、`tim.c`、`i2c.c`、`dma.c`、`usart.c` 和中断文件只在 `USER CODE` 区域内手工修改。业务逻辑放入独立文件，避免重新生成工程时被覆盖。

### 3.2 单一电机控制出口

任何模块都不得直接同时控制左右电机。应用状态机只生成运动请求，控制层把请求转换为左右轮目标值，最终由一个电机输出函数调用 TB6612 驱动。严重故障、人工停止和任务完成都通过同一安全停车入口生效。

### 3.3 非阻塞调度

运行阶段不得使用长时间 `HAL_Delay()`。传感器采样、灯光、OLED、串口、任务状态机和控制器由 `HAL_GetTick()` 或已有 20 ms 控制节拍调度。中断只采集数据或置位标志，不执行 OLED、串口和复杂 I2C 操作。

### 3.4 编译结果与实车结果分开记录

所有结论必须区分：主机测试通过、Keil 编译通过、已生成 HEX、已烧录、实车现象已验证。任何软件验证不得替代实车验证。

### 3.5 中文编码

新增和修改的 C、H、Markdown 文件统一使用 UTF-8 编码，中文注释必须能够在编辑器中正常阅读。Keil 工程编译前执行编码检查，禁止再次引入替换字符或乱码注释。

## 4 总体分层

### 4.1 配置层

目录：`Core/Inc/config/`

- `app_config.h`：模块功能开关、任务模式和调度周期。
- `car_parameters.h`：PWM、PID、转弯、颜色、距离、电池和超时参数。
- `hardware_map.h`：对 CubeMX 引脚和外设句柄提供语义化别名。

配置层不执行硬件操作。所有可调参数集中保存，避免散落在 `main.c` 和各驱动中。

### 4.2 驱动层

保留并整理以下现有驱动：

- `tb6612.c/.h`：左右电机方向和 PWM。
- `oled_driver.c/.h`、`soft_i2c.c/.h`：OLED 显示。
- `key.c/.h`：USER 按键原始输入；补充非阻塞消抖接口。
- `speed_measure.c/.h`：TIM4 双路轮速捕获。
- `tcs3472.c/.h`：TCS34725 颜色数据读取。
- `hc_sr04.c/.h`：TIM1 输入捕获测距；修正触发脉冲和固定偏移问题。
- `MPU6050_DMP/`：MPU6050、DMP 和 FIFO 数据读取。

驱动层返回明确的成功、未就绪、超时或硬件错误，不直接决定车辆任务状态。

### 4.3 控制层

目录：`Core/Src/control/` 与 `Core/Inc/control/`

- `motion_control.c/.h`：统一的前进、转向、原地旋转、停车和左右轮目标输出。
- `line_follow_control.c/.h`：迁移现有 AO PID 与外侧 DO 急弯救援算法。
- `speed_control.c/.h`：保存真实轮速、目标轮速和后续闭环接口；功能开关关闭时使用开环 PWM。
- `turn_control.c/.h`：使用 Yaw 增量执行定角转弯，并提供完成、超时和传感器失效结果。

控制层不得包含普通或高级驾照的路线顺序。

### 4.4 服务层

目录：`Core/Src/services/` 与 `Core/Inc/services/`

- `scheduler.c/.h`：统一产生 10 ms、20 ms、50 ms、100 ms、200 ms 和 500 ms 到期事件。
- `sensor_service.c/.h`：汇总循迹、Yaw、轮速、颜色、距离和电池数据，附带有效标志与最后更新时间。
- `indicator_service.c/.h`：启动三次双闪、停车双闪、左右转向灯和 LED 后备报码。
- `display_service.c/.h`：正常任务页、传感器页和故障页切换。
- `error_manager.c/.h`：故障登记、清除、优先级、轮播和查询。
- `self_test.c/.h`：上电自检状态机。
- `safety_service.c/.h`：把严重故障、人工停止和任务异常统一转换为安全停车请求。

### 4.5 应用层

目录：`Core/Src/app/` 与 `Core/Inc/app/`

- `app_controller.c/.h`：选择待机、普通驾照、高级驾照、诊断或故障模式。
- `normal_mission.c/.h`：启动双闪、循迹、红停绿行、障碍停车、转弯、返航和终点停车。
- `advanced_mission.c/.h`：A、B、C、D 点位、圆圈、八字、多圈计时和挑战任务。
- `route_detector.c/.h`：根据循迹特征、Yaw、轮速里程和路段上下文产生点位或阶段事件。
- `command_parser.c/.h`：解析电脑通过 USART3 发送的模式选择、启动、停止、状态查询和故障确认命令。

应用层只调用服务层和控制层接口，不直接读写 HAL 外设。

### 4.6 串口控制协议

上电默认不选择驾照并保持停车。电脑通过 USART3 使用以下 ASCII 命令：

- `MODE=NORMAL`：普通驾照。
- `MODE=CIRCLE`：高级圆圈。
- `MODE=EIGHT`：高级八字。
- `MODE=STABLE`：高级三圈稳定行驶。
- `MODE=CHALLENGE`：高级圆圈与八字交替挑战。
- `START`：启动当前已选择模式。
- `STOP`：立即停车并返回等待。
- `STATUS?`：返回模式、任务状态、传感器状态和活动故障。
- `ERRORS?`：返回全部活动故障。
- `ACK`：故障消失后解除安全停车锁定，不自动启动。

运行期间拒绝 `MODE=...`，必须先停止。严重故障不能被 `START` 绕过。USER 按键仍可启动或停止当前已选择模式。

## 5 主循环数据流

1. 中断更新 MPU 就绪标志、定时器捕获数据和 20 ms 控制请求。
2. `scheduler` 根据当前毫秒时间产生周期事件。
3. `sensor_service` 消费 MPU FIFO，更新循迹、轮速、颜色、距离和电池快照。
4. 各驱动和服务把通信失败、数据超时或数值异常上报给 `error_manager`。
5. `self_test` 或当前任务状态机读取传感器快照并生成运动请求。
6. `safety_service` 检查严重故障和人工停止；必要时覆盖运动请求为安全停车。
7. 控制层计算左右轮输出，唯一地调用 TB6612。
8. `indicator_service` 更新双闪、转向灯或 LED 报码。
9. `display_service` 低频刷新正常页面或故障页面。
10. USART3 低频输出结构化诊断记录。

## 6 故障管理设计

### 6.1 故障记录

每条活动故障包含：

- 模块编号。
- 故障码。
- 严重程度。
- 首次发生时间。
- 最近发生时间。
- 连续发生次数。
- 是否仍然活动。
- 是否允许自动恢复。

故障表使用固定大小静态数组，不使用动态内存。

### 6.2 模块编号

- `ERR_MODULE_SYSTEM`
- `ERR_MODULE_ADC`
- `ERR_MODULE_LINE_SENSOR`
- `ERR_MODULE_MPU6050`
- `ERR_MODULE_SPEED_LEFT`
- `ERR_MODULE_SPEED_RIGHT`
- `ERR_MODULE_COLOR`
- `ERR_MODULE_ULTRASONIC`
- `ERR_MODULE_BATTERY`
- `ERR_MODULE_MOTOR`
- `ERR_MODULE_MISSION`
- `ERR_MODULE_DISPLAY`

### 6.3 严重程度

- `ERROR_LEVEL_INFO`：记录但不改变车辆动作。
- `ERROR_LEVEL_WARNING`：允许降级运行，OLED 显示警告。
- `ERROR_LEVEL_FATAL`：立即安全停车并双闪，任务进入故障状态。

通信偶发失败先作为警告；超过连续次数或数据超时时间后升级为严重故障。恢复后清除活动标志，但严重故障恢复不自动重启任务，必须由 USER 按键重新确认。

### 6.4 上电自检

上电自检按以下顺序执行：

1. 内部配置和状态初始化。
2. ADC 校准与 DMA 启动。
3. MPU6050 地址探测和 DMP 初始化。
4. TCS34725 设备 ID 探测。
5. 超声波定时器和首次有效回波检查。
6. 左右轮测速通道静态就绪检查；静止状态不要求出现脉冲。
7. 电池 ADC 范围检查。
8. OLED 初始化与串口启动标记。

功能开关关闭的模块显示为禁用，不报故障。自检为非阻塞状态机；只有 MPU6050 DMP 库自身要求的初始化等待保留，并在 OLED 上明确显示当前步骤。

### 6.5 OLED 故障页

严重故障页面固定显示四行信息：

```text
ERROR 01/03
MOD:MPU6050
CODE:DATA TIMEOUT
MOTOR STOP
```

警告页面使用 `WARNING` 标题。多条故障按严重程度、发生时间排序，每 2 秒轮播一次。只更新变化行，不在高频路径清屏。

OLED 自身无法完成自检闭环，因此 `ERR_MODULE_DISPLAY` 只通过 USART3 和 LED 报码输出。

### 6.6 后备诊断

USART3 输出模块、故障码、级别、时间和次数。核心板 LED 使用重复闪烁组表示模块编号；严重故障期间左右灯保持双闪，核心板 LED 独立报码。

## 7 可复用代码与迁移策略

### 7.1 原样保留后封装

- CubeMX 外设初始化文件。
- MPU6050 DMP 库。
- OLED 字库和底层发送函数。
- USART3 重定向和基础收发。

### 7.2 迁移到新层次

- `car_control.c` 中的 PID、软启动、死区、积分限幅和外侧 DO 救援迁移到 `line_follow_control.c`。
- `main.c` 中的连续 Yaw 展开与阶段累计迁移到 `turn_control.c` 和任务状态机。
- `main.c` 中的 ADC DMA 启动、MPU 最高优先级消费和低频 OLED、串口调度迁移到对应服务。

### 7.3 修正后复用

- `speed_measure.c`：明确单位、溢出计算和停止超时。
- `tcs3472.c`：增加通信错误返回、原始数据有效性和连续识别确认。
- `hc_sr04.c`：使用微秒级触发、删除未经验证的固定 3.8 cm 偏移、增加无回波超时。
- `key.c`：增加基于时间的消抖。
- 电池采样：从提交 `52148dd` 恢复换算思路，同时把电池通道加入当前循迹 ADC 方案。
- 灯光和颜色整合逻辑：参考提交 `84fc8ec`，按新服务接口重新实现，不整段复制旧 `main.c`。

## 8 安全行为

以下情况必须请求安全停车：

- USER 在运行中按下停止键。
- MPU6050 在需要定角转弯或计圈时持续无有效数据。
- 循迹 ADC、DMA 或任务状态机发生严重错误。
- 电池电压低于严重阈值。
- 普通或高级任务超过路段最大允许时间。
- 状态枚举进入非法值。

安全停车后 PWM 归零，任务状态冻结，左右灯双闪，OLED 显示故障。恢复条件满足后仍保持等待，直到 USER 再次确认。

## 9 测试与验证

### 9.1 主机侧单元测试

对以下纯逻辑进行测试：

- 故障登记、去重、升级、清除和最高优先级选择。
- 多故障轮播顺序。
- 严重故障触发安全停车。
- 严重故障恢复后不会自动重启。
- 普通和高级任务状态转移。
- Yaw 跨正负 180 度的连续展开。
- 灯光模式的次数和时间边界。

### 9.2 静态检查

- 新增文件 UTF-8 解码成功。
- 不包含 Unicode 替换字符。
- CubeMX 生成文件的手工代码位于 `USER CODE` 区域。
- 应用层不直接调用 HAL 电机和灯光接口。
- `main.c` 不再保存完整任务业务逻辑。

### 9.3 目标编译

使用 Keil ARM Compiler 5.06 update 7 执行完整 Rebuild，要求 `0 Error(s), 0 Warning(s)` 并生成非空 HEX。

### 9.4 实车验证顺序

1. 架空车轮验证电机方向、停止和灯光。
2. 验证循迹 ADC、DO 和 PID 转向方向。
3. 验证左右轮测速单位。
4. 验证 MPU6050 Yaw、跨界和定角转弯。
5. 验证红绿牌阈值。
6. 验证超声波距离和停车阈值。
7. 验证电池电压与万用表差异。
8. 逐状态验证普通驾照。
9. 逐路段验证高级驾照。
