# PID 循迹、姿态计圈与自动掉头设计

## 1. 目标与指导书依据

本设计服务于《第 6 次课程实验指导书》第 11.3 节和第 11.4 节：

- 使用两个内侧 TCRT5000 的 AO 模拟量进行 PID 循迹。
- 小车先连续完成两圈顺时针循迹。
- 顺时针两圈结束后自动向右掉头 180 度。
- 随后连续完成两圈逆时针循迹并自动停车。
- 行驶过程中尽量减少频繁的左右剧烈摆动。

指导书中的 PID 结构和初始参数保持不变；只修正示例代码中变量名与实际引脚不一致的明显笔误。

## 2. 已确认的用户决策

- 原来连续执行 12 次、每次 90 度右转的姿态任务保持沉默，不再进入调度。
- MPU6050 的 DMP、FIFO、Yaw 解算和跨正负 180 度展开逻辑恢复工作，但只服务于计圈和掉头。
- 使用 Yaw 累计角度计圈：一圈约 360 度，两圈目标为 720 度。
- 中途掉头沿用已验证过的向右转电机动作，Yaw 累计达到 180 度后结束掉头。
- 必须避免 MPU FIFO 的数据产生速度长期大于主循环消费速度。
- OLED 保留 ADC、DMA、MPU 初始化及运行错误提示。

## 3. 硬件与外设配置

### 3.1 TCRT5000 接线

- 左内侧传感器 AO 接 PB0，即 ADC1_IN8。
- 右内侧传感器 AO 接 PA7，即 ADC1_IN7。
- PA6 和 PB1 保留为外侧传感器 DO 输入，但第一版严格按照指导书，不让外侧 DO 参与 PID 计算。

### 3.2 ADC 与 DMA

- ADC1 开启扫描转换，规则通道数为 2。
- Rank 1 配置 PB0/ADC1_IN8，DMA 缓冲区下标 0 表示左侧。
- Rank 2 配置 PA7/ADC1_IN7，DMA 缓冲区下标 1 表示右侧。
- DMA1 Channel 1 使用半字、存储器地址递增和循环模式。
- 按指导书顺序完成 ADC 校准、`HAL_ADC_Start()` 和 `HAL_ADC_Start_DMA()`。
- ADC 或 DMA 启动失败时禁止启动任务，停车并在 OLED、串口显示错误。

### 3.3 MPU6050

- 保留 I2C 地址 0x68/0x69 探测和 DMP 初始化。
- 保留 PA8 数据就绪中断；中断回调只置位，不在中断中读取 I2C、刷新 OLED 或控制电机。
- DMP 输出频率保持 100 Hz，主循环每 10 ms 主动补读一次。
- 继续使用现有 FIFO 追读策略，一次调用最多消费 16 帧并采用最新姿态，避免长期读取旧数据。

## 4. 调度与实时性约束

主循环任务按以下优先顺序处理：

1. 消费 MPU6050 FIFO 并更新最新 Yaw。
2. 处理 USER 急停或启动事件。
3. 推进实验状态机。
4. 每 50 ms 执行一次 PID 循迹控制。
5. 按低频率刷新 OLED 和输出串口诊断。

以下规则用于避免此前的实时性问题：

- MPU 读取不依赖单个布尔中断边沿，10 ms 定时补读作为第二触发源。
- OLED 和串口不得出现在 MPU 消费、ADC DMA 回调或 SysTick 中断中。
- OLED 最快每 200 ms 更新一次，串口诊断最快每 200 ms 输出一次。
- PID 热路径不执行阻塞式 ADC 轮询，只读取 DMA 已搬运的最新数组。
- 周期任务使用 `HAL_GetTick()` 的时间差判断；即使低优先级刷新偶尔延迟，也不会重复补执行多次阻塞任务。
- 电机只由实验状态机和 PID 控制出口写入，旧姿态任务、颜色、超声波及数字循迹分支不得同时争抢电机。

## 5. 实验状态机

状态定义如下：

- `TRACK_WAIT_START`：上电停车，等待 USER 按键。
- `TRACK_CW`：PID 循迹并累计顺时针 Yaw，目标 720 度。
- `TRACK_TURN_AROUND`：暂停 PID，沿用向右转动作，累计 180 度。
- `TRACK_CCW`：清空 PID 历史后重新循迹，累计逆时针 Yaw，目标 720 度。
- `TRACK_COMPLETE`：停车并显示任务完成。
- `TRACK_ERROR`：发生 ADC、DMA 或 MPU 错误后停车并显示原因。

USER 按键行为：

- 在等待状态按下：清零 PID 与所有角度累计量，开始顺时针循迹。
- 在任意运行状态按下：立即停车并返回等待状态。
- 在完成或错误状态按下：清除任务运行状态；错误只有在外设已经恢复后才允许重新启动。

## 6. Yaw 连续化、计圈与掉头

每次得到新 Yaw 后计算当前值与上一次值的差：

- 差值大于 180 度时减去 360 度。
- 差值小于负 180 度时加上 360 度。
- 这样可以正确处理 DMP Yaw 从正 180 度跳到负 180 度，或反向跳变。

当前工程已经验证 `POSE_YAW_DIRECTION=-1.0f` 可把物理顺时针旋转映射为正进度，因此：

- 顺时针阶段累计 `yaw_delta * POSE_YAW_DIRECTION`，达到 720 度后只触发一次状态切换。
- 掉头阶段使用相同方向累计，达到 180 度后停止右转。
- 逆时针阶段累计上述值的相反数，达到 720 度后停车。
- 反向抖动会抵消已累计角度；累计进度最低限制为 0，防止起步抖动产生负圈数。

状态切换时重置上一帧 Yaw 基准，避免把停车或切换瞬间误算到下一阶段。

## 7. PID 循迹

第一版保持指导书的结构和初始参数：

```c
Kp = 1.5f;
Ki = 0.05f;
Kd = 2.0f;
Base_Speed = 3500;
```

控制流程：

1. 从 DMA 缓冲区读取左、右 ADC。
2. 计算 `Error = Right_ADC - Left_ADC`。
3. 更新带正负 8000 限幅的积分项。
4. 计算比例、积分和微分输出。
5. 左轮速度为基础速度加 PID 输出，右轮速度为基础速度减 PID 输出。
6. 两侧速度分别限制到 0～7200。
7. 通过 TB6612 驱动左右电机。

进入掉头、停止、错误或切换循迹方向时，清零 `Last_Error` 与 `Integral`，防止旧方向的积分残留影响重新起步。

指导书第 27 页使用了未定义的 `adc_ch7_value`、`adc_ch9_value`；实现时统一使用 DMA 中的 `adc_left_value`、`adc_right_value`。当前内侧引脚对应 ADC1_IN8 和 ADC1_IN7，不使用 IN9。

## 8. OLED 与串口

正常运行时 OLED 显示：

- 当前状态：`WAIT`、`CW`、`TURN`、`CCW` 或 `DONE`。
- 左右 ADC 原始值。
- 当前圈数或阶段角度进度。
- 最新 Yaw。

错误状态优先覆盖普通页面：

- `ADC CAL ERR`
- `ADC START ERR`
- `ADC DMA ERR`
- `ADC RUN ERR`
- `MPU NOT FOUND`
- `DMP INIT FAIL`

串口低频输出 ADC、PID 输出、Yaw、当前状态与累计角度，用于调参和确认状态切换，不逐帧打印。

## 9. 代码边界

- `timer_pwm.ioc`、`Core/Src/adc.c`、`Core/Src/gpio.c`：双通道 ADC 和引脚配置。
- `Core/Src/car_control.c`、`Core/Inc/car_control.h`：PID 控制函数、PID 状态复位和电机输出。
- `Core/Src/main.c`：MPU 数据消费、计圈/掉头状态机、USER 按键、OLED 与串口调度。
- 原 12 段姿态任务代码可以暂时保留以便追溯，但不得被按键、主循环或任何实验状态调用；如果保留会造成维护歧义，则在实施阶段删除其私有状态和函数。
- 颜色和超声波功能继续保持静默。

## 10. 验证标准

### 静态与编译验证

- `.ioc`、`adc.c`、`gpio.c` 与 `main.h` 的 PA7/PB0 配置一致。
- 中文源码使用 UTF-8 BOM，严格解码无乱码。
- Keil Rebuild 达到 0 Error、0 Warning。
- Git diff 不包含用户自己的 `MDK-ARM/timer_pwm.uvprojx` 改动。

### 架空车轮验证

- 白面与黑线移动时左右 ADC 数值能够明显变化，且左右通道没有接反。
- MPU 初始化成功，连续转动车体时 Yaw 无明显长时间滞后。
- 运行中按 USER 键能够立即停车。
- 模拟达到顺时针 720 度后只进入一次掉头，掉头 180 度后进入逆时针阶段。

### 实车验证

- 完成两圈顺时针循迹。
- 自动向右掉头约 180 度。
- 完成两圈逆时针循迹并停车。
- OLED 状态与实际阶段一致。
- 串口数据中没有持续增长的姿态延迟，循迹过程中没有因 OLED 或串口刷新产生明显周期性停顿。

编译通过只证明代码和配置能够构建；烧录成功也不等于计圈、掉头和 PID 参数已经通过实车验证。PID 与角度阈值最终需要根据赛道和车辆实测调整。
