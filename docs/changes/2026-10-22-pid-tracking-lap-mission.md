# PID 模拟量循迹、姿态计圈与自动掉头

## 实验目标与指导书依据

按照《第 6 次课程实验指导书》第 11.3、11.4 节：

- 使用两个内侧 TCRT5000 的 AO 电压进行 PID 循迹。
- 连续完成两圈顺时针循迹。
- 顺时针两圈结束后自动向右掉头 180 度。
- 随后完成两圈逆时针循迹并自动停车。
- 减少循迹过程中的频繁左右剧烈摆动。

## 配置与源码修改

### ADC 与 DMA

- 左内侧 AO 接 PB0/ADC1_IN8，配置为 Rank 1，对应 `adc_dma_data[0]`。
- 右内侧 AO 接 PA7/ADC1_IN7，配置为 Rank 2，对应 `adc_dma_data[1]`。
- ADC1 使用扫描、连续转换和软件启动，DMA1 Channel 1 使用半字、地址递增和循环模式。
- PA6、PB1 仍保留为外侧 DO 输入，但第一版 PID 不读取这两路。
- 按指导书顺序执行 ADC 校准、`HAL_ADC_Start()` 和 `HAL_ADC_Start_DMA()`。

### PID 循迹

- `car_control.c` 新增 `Line_Following_PID()`、`Line_Following_PID_Reset()` 和诊断输出接口。
- 初始参数保持指导书原值：`Kp=1.5f`、`Ki=0.05f`、`Kd=2.0f`、`Base_Speed=3500`。
- 偏差保持指导书定义：右 ADC 减左 ADC。
- 积分项限制在正负 8000，左右轮最终 PWM 限制在 0～7200。
- 停止、掉头和方向切换时清空积分与上一次误差。

### 指导书示例笔误处理

指导书第 27 页先定义了 `adc_left_value`、`adc_right_value`，后续电压换算却使用未定义的 `adc_ch7_value`、`adc_ch9_value`。当前实际内侧引脚是 PB0/ADC1_IN8 与 PA7/ADC1_IN7，因此代码统一直接使用 DMA 左右采样值，不使用 IN9，也不改变指导书 PID 算法。

### MPU6050 与任务状态机

- 原连续 12 次、每次 90 度的姿态任务已从源码和调度中移除。
- 恢复 MPU6050 地址探测、DMP 初始化、PA8 数据就绪中断和 FIFO 消费。
- DMP 维持 100 Hz；主循环除中断标志外每 10 ms 主动补读一次。
- 使用跨正负 180 度展开后的有符号 Yaw 增量累计角度。
- 任务顺序为：顺时针 720 度 → 向右转 180 度 → 逆时针 720 度 → 停车。
- USER 按键在等待/完成状态启动任务，在运行状态立即停车；错误状态不允许掩盖故障后强行启动。

## 避免 FIFO 再次积压的措施

本次把 MPU FIFO 消费放在主循环最高优先级位置，并明确限制低优先级任务：

1. MPU 每 10 ms 至少得到一次消费机会，不完全依赖可能合并的单比特中断标志。
2. 沿用驱动中最多追读 16 帧并采用较新姿态的策略。
3. OLED 与串口均限制为每 200 ms 最多一次。
4. MPU 消费块内不打印、不刷新 OLED、不控制电机。
5. PID 每 50 ms 读取 DMA 最新值，不执行阻塞式 ADC 轮询。
6. SysTick 只置位 50 ms 请求，主循环延迟后不会补跑多次 PID。

## OLED 与串口诊断

正常页面显示状态、左右 ADC、当前阶段角度和最新 Yaw。错误页面优先显示：

- `ADC CAL ERR`
- `ADC START ERR`
- `ADC DMA ERR`
- `ADC RUN ERR`
- `MPU NOT FOUND`
- `DMP INIT FAIL`

串口每 200 ms 最多输出一次状态、左右 ADC、PID 输出、Yaw 和阶段累计角度，不再逐帧打印姿态。

## 编译验证

- RED 构建：新状态机只有接口、没有实现时，Keil 确认产生未定义错误，证明新路径参与编译。
- 第一次 GREEN 构建发现 `key.c` 依赖的 `key_rval` 在主程序收敛时被移除。
- 查明 `key.c` 通过 `extern uint8_t key_rval` 保存按键扫描值后，在 `main.c` 恢复该模块接口变量。
- 修复后使用 ARM Compiler 5.06 update 7 完整 Rebuild：`0 Error(s), 0 Warning(s)`，已生成 HEX。
