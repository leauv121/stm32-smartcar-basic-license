# 2026-10-28：红牌停车锁存与双灯常亮

## 现象

普通模式行驶途中识别到红牌后能够停车，但红牌离开视野后车辆可能自行恢复。要求是确认红牌后持续停车并让左右灯常亮，只有稳定确认绿牌后才恢复行驶。

## 证据与根因

- `normal_mission.c` 已经把红牌状态锁存在 `NORMAL_RED_WAIT`，且该状态只有 `green_detected` 能解除；现有状态机测试也证明时间流逝、无颜色和障碍物事件都不能解除停车。
- 因此车辆在没有真实绿牌时恢复，说明运行时颜色链路产生了错误的绿色输入，而不是状态机主动取消停车。
- 原实现先调用 `RGB_normalize()`，随后 `RGBtoHSL()` 又按 Clear 通道归一化一次，导致颜色值被重复归一化。
- 原分类只检查色相，不检查饱和度。白色、灰色和弱光背景的色相抖动可能落入绿色范围，连续确认后错误解除红牌停车。

## 修改

- 删除 `ReadColor()` 中多余的 `RGB_normalize()`，由 `RGBtoHSL()` 完成一次 RGBC 归一化。
- 新增纯函数 `DriverAlgorithms_ClassifyColor()`；饱和度低于 `30%` 时一律返回无颜色，再按既有色相范围识别红色和绿色。
- 保留连续 3 个样本确认机制。红牌确认后，即使后续样本为无颜色也保持停车；只有连续 3 次绿色才能恢复。
- 新增 `INDICATOR_BOTH_ON`。红牌等待期间左右灯持续常亮；障碍物停车仍使用原来的双闪。
- 增加颜色分类、双灯常亮和红牌停车输出的回归测试。

## 验证

- RED：颜色测试因分类函数不存在而编译失败；指示灯和任务测试因 `INDICATOR_BOTH_ON` 不存在而编译失败。
- GREEN：Windows GCC 原生测试 `18/18` 通过。
- 源码边界检查通过。
- UTF-8 检查通过。
- Keil ARM Compiler 5.06 update 7 全量 Rebuild：`0 Error(s), 0 Warning(s)`，并重新生成 HEX。
- 实车验证：用户确认当前版本运行正常，红牌停车、双灯常亮、移开红牌后保持停车以及绿牌恢复行为未再出现问题。

## 未验证

- `30%` 饱和度门槛已在当前实车环境验证可用，但不同赛场光照和牌面材质尚未覆盖；如果后续漏检，应记录 HSL 数据后调整门槛，不能取消红牌锁存。
