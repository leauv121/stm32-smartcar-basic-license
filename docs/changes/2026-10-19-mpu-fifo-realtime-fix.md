# 2026-10-19：MPU6050 FIFO 实时性与姿态角少读问题

## 1. 修改背景

实验要求使用 MPU6050 DMP 实时读取 Pitch、Roll、Yaw，在 OLED 显示姿态，并让小车每隔 1 秒旋转 90 度，连续转 3 圈。

在解决 MPU 未找到、DMP 初始化失败和 OLED 不显示等问题后，姿态数据能够读取，但实车顺时针旋转时出现稳定少读：

- 实际旋转 $90^\circ$，Yaw 约为 $-71.6^\circ$。
- 实际旋转 $180^\circ$，Yaw 约为 $-144.4^\circ$。
- 实际旋转 $270^\circ$，Yaw 显示约为 $+145.4^\circ$；跨越 $\pm180^\circ$ 展开后约为 $-214.6^\circ$。
- 换用其他小车运行同一份程序，比例仍接近 $70/90$，软件共因的可能性明显高于机械个体差异。
- 停止旋转后读数基本保持，不像单纯刹车惯性造成的过冲。

曾尝试使用 `POSE_YAW_SCALE=1.55f` 补偿，但第一圈接近目标后，第二圈和第三圈误差继续增大。这说明比例系数是在掩盖数据链问题，而不是完成可靠标定。

## 2. 排查过程与证据

### 2.1 已确认的硬件问题

早期出现过 `MPU NOT FOUND`、`DMP INIT FAIL` 和错误码 08。更换 MPU 模块后初始化恢复，说明当时确实存在损坏或不兼容的传感器模块。

但是更换模块只能解决“能否初始化”，不能解释不同车辆运行同一固件时都出现相似的 $70/90$ 比例，因此继续检查软件数据链。

### 2.2 与参考工程对比

对 `E:/timer_pwm.zip` 解压后，沿着“DMP 初始化 → FIFO 读取 → 欧拉角换算 → OLED 显示”进行了对比。

参考工程的重要特点：

- `DEFAULT_MPU_HZ` 为 100 Hz，而当前工程原来为 200 Hz。
- `MPU6050_DMP_GetData()` 根据 `more` 连续读取 FIFO，最多追读 16 帧，并使用较新的四元数。
- 即使外部中断没有到达，主循环每 10 ms 也会尝试读取 FIFO。
- OLED 每 200 ms 更新一次，而不是每个姿态包都刷新。
- 串口不逐帧输出完整姿态信息。
- OLED 直接显示原始 DMP Yaw，没有隐藏的角度比例系数。

参考工程配置的是 MPU6500，`WHO_AM_I` 期望值为 `0x70`，因此没有直接覆盖其驱动，只移植了与芯片型号无关的调度和 FIFO 消费策略。

### 2.3 当前工程中的实时性问题

原程序以 200 Hz 产生 DMP 数据，每 $5\,\text{ms}$ 产生一帧。每次成功读取后却立即：

1. 完整刷新 Pitch、Roll、Yaw 和 TURN 四行 OLED。
2. 使用逐字符阻塞式 `printf` 输出姿态。
3. 在主循环中无周期限制地读取和打印颜色数据。

串口一行约 50 字符，在 115200 bit/s、每字符约 10 bit 时，仅发送时间约为：

$$
t\approx\frac{50\times10}{115200}\approx4.34\,\text{ms}.
$$

这已经接近一个 5 ms 姿态周期，尚未计算软件 IIC OLED 和颜色读取时间。

外部中断回调只执行：

```c
mems_data_rdy_flag = 1U;
```

多个中断在主循环繁忙时会合并成同一个布尔标志。原 `MPU6050_DMP_GetData()` 每次又只读取一帧，并忽略 `more`，因此 FIFO 生产速度可能长期大于消费速度，造成旧帧积压、溢出复位或中断边沿丢失。

## 3. 根因判断

当前最强的软件证据指向：高频阻塞式 OLED/串口/颜色任务占用了主循环，MPU FIFO 没有及时消费；单比特中断标志又无法表示积压帧数，最终表现为显示旧角度和旋转区间丢失。

这比“陀螺仪固定少读约 20%”更符合以下事实：

- 多辆车运行同一固件结果接近。
- 参考程序使用相同欧拉角公式却不依赖比例系数。
- 原程序存在明显的生产者—消费者速率失衡。
- `1.55` 只能短期补偿，连续旋转会累积错误。

该根因已得到源码对比和时序分析支持，但必须通过烧录后的实车角度实验才能最终闭环验证。

## 4. 实际修改

### `Core/Src/MPU6050_DMP/MPU6050_DMP/inv_mpu.h`

- `DEFAULT_MPU_HZ`：200 Hz 调整为 100 Hz。

### `Core/Src/MPU6050_DMP/MPU6050_DMP/mpu6050_dmp.c`

- MPU INT 设置为低电平有效，匹配 PA8 下降沿 EXTI。
- 根据 FIFO 的 `more` 标志连续追读，单次最多 16 帧。
- 使用最新读取的四元数计算欧拉角。
- 增加四元数模长检查和 Pitch 输入范围限制。
- 角度换算改用精确的 $180/\pi\approx57.2957795$。

### `Core/Src/main.c`

- `POSE_YAW_SCALE` 从 `1.55f` 恢复为 `1.0f`。
- MPU 增加 10 ms 定时补读，不再完全依赖外部中断边沿。
- 姿态控制每个有效数据包更新。
- OLED 和姿态串口分别限制为 200 ms 更新一次。
- 颜色数据每 60 ms 读取一次，颜色诊断串口每 300 ms 输出一次。
- 超声波避障继续保持关闭，不参与本次排查。

3. 继续旋转到 $180^\circ$、$270^\circ$ 和 $360^\circ$，观察 $\pm180^\circ$ 展开是否连续。
4. 停止后等待 2 秒，确认 OLED 是否到达最终角度，而不是停留在旧帧。
5. 启动自动任务，记录 12 次旋转的停止角度和累计误差。
6. 若原始 Yaw 仍存在稳定比例误差，再单独进行传感器标定；在数据链验证前不重新加入比例系数。

## 7. 本次经验

- 模块分别正常，不代表组合后满足实时性。
- 中断标志是通知，不是事件计数器。
- FIFO 必须按生产速度及时消费，并处理积压和溢出。
- 控制、采样、显示和日志应使用不同频率。
- 调试输出本身会改变被调试系统的时序。
- 标定只能修正真实、可重复的测量误差，不能补偿漏帧和旧数据。
- 编译通过、初始化成功和实车行为正确是三种不同证据。
