# 2026-10-25：掉头回线与外侧救线负反馈

## 现象

车辆按固定角度掉头后可能尚未对准黑线就恢复基础速度，直接冲出轨迹。普通弯道中，外侧传感器触发固定差速后也可能长期卡在侧边，或外侧刚释放就过早交还 PID。

## 根因

1. `NORMAL_AVOID_TURN` 完成后直接进入返程，没有独立的低速寻线状态。
2. 外侧救线是瞬时条件分支，没有锁存救线方向，也没有验证中间模拟传感器已经重新捕获黑线。
3. 循迹控制器此前在每次主循环都更新，软启动和后续确认计数不一定对应新的 20 ms 传感器样本。
4. 掉头采用 `4500/0` 单轮支点转弯，角速度差较小且转弯半径较大。

## 修改

- 掉头目标角度标定为 190 度。
- 粗掉头改为左右轮反向 `3200/-3200`，形成半径更小的原地旋转。
- 新增 `NORMAL_REACQUIRE_LINE`，粗掉头后以 `2400/700` 低速继续向右寻找黑线。
- 外侧救线改为锁存状态；外侧释放后仍保持救线，直到中间两路 ADC 连续 3 个新样本确认回中。
- 回中初始阈值为两路 ADC 均不低于 `2000`，且左右差值绝对值不超过 `500`。
- 回中完成时把 PID 基础速度重新置为 `1800`，避免交接瞬间按 `3700` 前冲。
- 循迹输入增加 `sample_ready`；只有 ADC/DMA 校验通过并成功更新循迹快照时才算新样本，没有新数据时保持上一电机输出且不累计确认次数。
- 救线或回线最多允许 150 个有效新样本，约 3 秒；仍未回中时输出归零并上报 `LINE / BAD VALUE` 致命故障，由安全层停车。

## 验证

- RED：旧接口没有强制回线入口、样本新鲜度或 `NORMAL_REACQUIRE_LINE` 状态，测试无法编译。
- GREEN：Windows GCC 主机测试 18/18 通过。
- Keil ARM Compiler 5.06 update 7 全量 Rebuild：`0 Error(s), 0 Warning(s)`。
- 已重新生成 `MDK-ARM/timer_pwm/timer_pwm.hex`。

## 未验证

- `2000` 黑线阈值和 `500` 回中误差范围需要根据实车黑白 ADC 数据校准。
- 必须架空车轮确认负 PWM 确实让右轮反转，并确认旋转方向为右转。
- 需要实车确认 190 度、原地旋转速度以及 `2400/700` 回线速度不会撞障碍物或越过黑线。
- 若 OLED 出现 `LINE / BAD VALUE`，应先读取中间 ADC 黑白实测值并调整回中阈值，而不是取消超时停车。
