# 2026-10-28：红牌快速确认与绿牌严格放行

## 现象

上一版本对红牌和绿牌都要求连续 3 个颜色样本。颜色任务每 `100 ms` 采样一次，因此两者都约需 $300\,\mathrm{ms}$。实车反馈红牌确认偏慢，而绿牌作为解除停车的条件需要更严格。

## 修改

- 新增 `DriverAlgorithms_ConfirmTrafficColor()`，集中管理交通颜色的确认策略。
- 红牌要求连续 2 个有效样本，理论确认时间约为 $200\,\mathrm{ms}$。
- 绿牌要求连续 5 个有效样本，理论确认时间约为 $500\,\mathrm{ms}$。
- 从已确认红色切换到绿色时，前 4 个绿色样本继续返回红色，第 5 个绿色样本才允许切换为绿色。
- 无颜色样本仍会清空候选计数；色相范围和 `30%` 饱和度门槛保持不变。
- 本次调整与待测的 `3800` 稳态循迹速度共同保留为未提交改动。

## 验证

- RED：新增行为测试后，编译因 `DriverAlgorithms_ConfirmTrafficColor()` 尚不存在而失败。
- GREEN：颜色算法定向测试通过，完整 Windows GCC 原生测试 `18/18` 通过。
- 源码边界检查通过。
- UTF-8 检查通过。
- Keil ARM Compiler 5.06 update 7 全量 Rebuild：`0 Error(s), 0 Warning(s)`，并重新生成 HEX。

## 未验证

- 红牌约 $200\,\mathrm{ms}$ 停车、绿牌约 $500\,\mathrm{ms}$ 放行尚未实车验证。
- 需要确认红牌响应速度足够，同时单次红色噪声不会误停；绿牌需要保持足够时间才能解除停车。
- 只有实车验证通过并得到用户明确同意后才允许提交。
