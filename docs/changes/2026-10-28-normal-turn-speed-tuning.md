# 2026-10-28：普通模式掉头提速与角度调整

## 现象

普通模式遇到障碍物后的原地掉头速度过慢，不能满足两秒内完成掉头的时间要求。原参数以 `3200/-3200` 驱动左右轮，粗掉头目标为 $190^\circ$。

## 证据与判断

- 电机 PWM 有效上限为 `7199`，原掉头指令只使用 `3200/-3200`，仍有明显提速余量。
- MPU6050 DMP 已按 $100\,\mathrm{Hz}$ 输出姿态，主循环由数据就绪中断或 $10\,\mathrm{ms}$ 补读触发，并一次最多追读 16 帧。
- 若两秒完成 $170^\circ$ 控制目标，平均角速度约为 $85^\circ/\mathrm{s}$，在 $100\,\mathrm{Hz}$ 下相邻姿态样本约变化 $0.85^\circ$。现有姿态更新能力足以支持本次提速，无需把 DMP 提升到 $200\,\mathrm{Hz}$ 并增加 I2C 与主循环负担。

## 修改

- `CAR_AVOID_TURN_TARGET_DEG`：先由 `190.0f` 改为 `180.0f`；实车出现惯性过转后，待测值进一步改为 `170.0f`。
- `CAR_AVOID_TURN_LEFT_SPEED`：由 `3200` 改为 `5000`。
- `CAR_AVOID_TURN_RIGHT_SPEED`：由 `-3200` 改为 `-5000`。
- 更新普通模式状态机测试，使其验证新的掉头轮速输出。
- 同步更新普通掉头与回线接管学习笔记中的参数说明。

## 验证

- RED：只修改测试后，`test_normal_mission` 在第 91、92 行分别报告期望 `5000/-5000`、实际 `3200/-3200`，测试退出码为 `2`。
- GREEN：修改生产参数后，`test_normal_mission` 定向测试退出码为 `0`。
- 完整 Windows GCC 原生测试通过：`18/18`。
- 源码边界检查通过。
- UTF-8 检查通过：133 个文件。
- Keil ARM Compiler 5.06 update 7 全量 Rebuild：`0 Error(s), 0 Warning(s)`，并重新生成 HEX。
- 实车验证：用户确认 `5000/-5000` 与 $170^\circ$ 控制目标运行正常，未再反馈过转问题。

## 未验证

- $180^\circ$ 控制目标曾经实车确认存在过转，当前 $170^\circ$ 已在本轮实车环境验证通过。
- 不同电池电压、轮胎抓地力和赛道表面仍可能改变惯性过冲；若后续再次过转，应先重新测量实际角度，不能直接修改姿态采样率。
