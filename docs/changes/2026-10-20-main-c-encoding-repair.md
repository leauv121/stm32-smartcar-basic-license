# main.c 中文注释编码修复

## 现象

Keil 中 `Core/Src/main.c` 的部分中文注释显示为“鍏堜繚璇……”一类乱码，而新加入的部分中文注释仍能正常显示。

## 证据与根因

- 修复前文件没有 UTF-8 BOM。
- 修复前文件无法通过严格 UTF-8 解码，但可以按 GBK 解码。
- 上一个 Git 版本中对应中文注释完整且可按 UTF-8 正确读取。
- 文件中同时存在原有 UTF-8 中文字节和后加入的 GBK 中文字节，Keil 按单一编码读取时必然有一部分显示错误。

根因是 `main.c` 曾被不同工具以不同字符编码读取和写回，形成混合编码文件。

## 修复方法

1. 从提交 `ac8322b` 恢复原有的正确中文注释。
2. 重新应用当前版本中的 ADC、按键采样和外设初始化逻辑。
3. 保留本次新增的 ADC 中文注释。
4. 将整个文件统一为带 BOM 的 UTF-8，并统一使用 CRLF 换行。

## 逻辑一致性检查

修复前后文件均去除注释和空白后再计算 SHA-256，结果完全一致：

```text
54d1a59fef2a96e870642a914af7f86df66abfe9556c3efe76b81e7fe735d3de
```

这证明修复只改变了注释、编码和排版，没有改变可执行 C 代码。

## 验证结果

- 编码检查：UTF-8 BOM 存在，严格 UTF-8 解码通过，没有替换字符。
- 中文检查：原有注释与 ADC 新注释均可正确读取。
- Keil Rebuild：ARM Compiler 5.06 update 7，`0 Error(s), 0 Warning(s)`。
- 未重新烧录；本次修改不改变固件逻辑。
